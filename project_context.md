# Sapient — Project Context

Canonical project description: goals, constraints, phase plan, architecture decisions, and file-by-file layout. readme.md is the public-facing summary; when the two disagree, this file wins.

## What Sapient is

Clinical reporting automation pipeline. Given a Statistical Analysis Plan (SAP) PDF, an agentic LangGraph pipeline generates submission-style R programs for ADaM datasets (admiral) and TLF outputs (rtables), validates them, and executes them against pharmaverse SDTM data.

Pipeline flow: SAP ingestion → LoT generation → mockshell generation → ADaM program generation → TLF program generation → validation → R execution.

## End-state vision (why the phases exist)

The full ambition, from the project's founding draft: **SAP + Protocol → endpoint extraction → LoT → mockshells → ADaM spec → ADaM programs (admiral) → TLF programs → submission-ready TLF outputs**, with a parallel SDTM layer (CRF annotation + raw data → sdtm.oak → SDTM datasets). The LoT is the critical fan-out point: it determines which TLFs exist, which ADaM datasets they need, and which SDTM domains those need. The LLM never generates clinical values — only R code over template functions, executed deterministically.

**Build order is backwards from the oracle, not front-to-back.** ADaM codegen has a ground-truth oracle (does it execute; does it match pharmaverseadam), so it gets hardened first. LoT/spec/mockshell generation have no oracle except a reference artifact or a human, so each is built only once there is an eval to score it against (pilot LoT list, pilot Define.xml, pilot table shells) plus a human sign-off gate. A fresh session should never start work at the front of the pipeline because it "comes first."

Superseded decisions from the founding draft — do not resurrect them: Neo4j (→ networkx), Gemma via Google AI Studio (→ NVIDIA Build, models in `config.py` only), FastAPI/MCP now (→ deferred phase), SDTM-layer generation now (→ Phase 2b). When any old note conflicts with this file, this file wins.

Two kinds of pipeline stages: **reasoning** (LoT, spec derivations — the model must comprehend the study; where accuracy is won/lost and where hallucination lives) and **mechanical** (code from a spec, SDTM from a mapping — deterministic given clean upstream metadata, which inherits the reasoning stages' errors). The whole game is upstream accuracy.

Guiding principles adopted this sprint:
- **Constraints over exemplars.** At temp 0 the model transcribes templates blindly; ground on machine-checkable constraints (signatures, real input columns, spec type/CT rules) + deterministic repair, not exemplars to mimic.
- **Controlled vocabularies over free generation.** ADaM dataset names come from `knowledge/adam_registry.py`; variables from the public ADaMIG standard (`knowledge/adamig_standard.py`) + spec; functions from extracted package signatures. Hallucination (the documented 21–50% clinical-LLM failure rate) is bounded structurally.
- **Rules-first.** The durable error class is format/type/CT conformance, not derivation logic. Precompile rules from the spec (`extract_spec_rules.R` → `spec_rules_block()`), check them deterministically (`check_conformance.R`, a P21/CORE-style check reversed from our own metadata), coerce at write time (xportr type/length/format).

## Constraints (these drive every decision)

- Solo developer
- No local GPU (Arch Linux, Intel integrated graphics) — all LLM calls via hosted APIs, embeddings run on CPU
- Free-tier APIs only (NVIDIA Build; rate limits and model rotation are real risks — GLM 5.2 already times out on current tier)
- Deadline: January 2027

Implications: generation speed is nearly irrelevant (outputs are cached by prompt hash, each program is generated once), so prefer slow-but-reliable models for codegen. Never burn LLM quota on checks a deterministic tool can do.

## Architecture decisions

- **LLM generates R code via template functions, not clinical values** — determinism by construction. Temperature 0, model pinned, outputs cached by SHA256 prompt hash. Note: changing a prompt template invalidates its cache entries by design.
- **Two model roles** (`REASONING_MODEL` for SAP comprehension/LoT/mockshells/validation, `CODEGEN_MODEL` for ADaM/TLF R code), defined in `config.py`. Current: REASONING=DiffusionGemma, CODEGEN=`mistralai/mistral-nemotron` with DiffusionGemma fallback. A/B history: DiffusionGemma fast (1–4s) but can't write long derivation chains and hallucinates names; Gemma 4 31B endpoint dead on free tier (persistent timeouts, 2026-07-12); Nemotron ~2s and clean admiral R; deepseek-v4-flash works but slow/verbose (probe results in git history). `llm_retry.py` handles rate limits, timeouts, and model fallback. Free-tier models rotate — re-probe when a model degrades (probe snippet: one-shot derivation ask against every `coder|deepseek|nemotron|qwen`-named model).
- **BDS vs OCCDS classification is a lookup, not LLM reasoning.** Known taxonomy gaps to handle: ADSL is neither (subject-level, own template); ADTTE is formally BDS but needs its own template family (CNSR, censoring derivations, EVNTDESC); unknown/custom dataset names must flag for human review, never silently default. The lookup buys the program skeleton; derivation logic (baseline flags, LOCF, visit windowing, criterion flags) remains LLM territory — that's the real variance.
- **LoT is the critical fan-out point** — everything downstream inherits its errors silently. Required mitigations: (a) coverage check — validate the LoT covers the SAP, not just that entries have fields ("which analyses in the SAP have no LoT entry?"); (b) human sign-off gate on the LoT before downstream generation — cheapest QC point in the pipeline; (c) explicit LoT-entry → required-ADaM-dataset → required-SDTM-domain mapping in the knowledge graph, so missing intermediate datasets fail loudly.
- **Deterministic checks run before LLM checks**, always (see Phase 1 exit criteria).
- **metacore enforces spec compliance** on all generated ADaM programs.
- **Domain-aware chunking** by clinical section boundaries, not token count. PubMedBERT embeddings for SAP chunks; if the same store later retrieves admiral docs or R code, eval a code-oriented embedding model first — don't assume PubMedBERT transfers.

## File-by-file description

**orchestration/state.py** — LangGraph state schema. TypedDict flowing between every node: study ID, SAP content, knowledge graph reference, LoT entries, mockshells, generated programs, validation results, error flags.

**orchestration/graph.py** — Builds the LangGraph StateGraph: nodes, edges, conditional routing. Entry is SAP ingestion; validator routes failed programs back to adam_generator for up to 3 selective regeneration rounds, then END.

**orchestration/llm_retry.py** — `create_with_retry()`: wraps `chat.completions.create` with exponential backoff on `RateLimitError`. Every node's LLM call goes through it.

**orchestration/nodes/sap_reader.py** — Chunks the SAP PDF by clinical section boundaries, embeds chunks into ChromaDB, extracts study metadata (study ID, compound, therapeutic area, primary endpoint, populations). Uses REASONING_MODEL.

**orchestration/nodes/lot_generator.py** — Reads knowledge graph + SAP chunks, extracts endpoints and analysis requirements, generates structured LoT — one entry per TLF with table number, title, population, data source, statistical method. Uses REASONING_MODEL. Hardest node in the pipeline.

**orchestration/nodes/mockshell_generator.py** — Generates a mockshell blueprint per LoT entry: column headers, row structure, footnotes, display conventions. Uses REASONING_MODEL.

**orchestration/nodes/adam_generator.py** — Takes LoT entries, metacore spec, and admiral function knowledge; generates R code per ADaM dataset. For datasets in `templates.adam_templates.ADAM_INPUTS` (ADSL, ADAE): LLM writes only the derivation block (`DERIVATION_PROMPT`, grounded with the real admiral template + real spec variable list), spliced between a deterministically-rendered header/footer. Other datasets fall back to the old full-skeleton prompt (`ADAM_PROMPT`). Uses CODEGEN_MODEL, temperature 0, prompt-cache-first.

**orchestration/nodes/tlf_generator.py** — Takes mockshells, ADaM datasets, LoT entries; generates R programs per TLF. Uses CODEGEN_MODEL, same caching.

**orchestration/nodes/validator.py** — Reviews generated R programs: metacore compliance, admiral function usage, population flag consistency. Runs the 6-check deterministic gate first (gate failures skip the LLM call), then the LLM review, then R execution + metacore compliance; stage-tags every failure and computes `real_pass_rate`. On regeneration rounds it re-validates only flagged programs, carrying prior results forward.

**knowledge/graph_store.py** — Knowledge graph on networkx. Nodes are study artifacts (SAP sections, ADaM datasets, SDTM domains, TLFs, population flags); edges are relationships.

**knowledge/vector_store.py** — ChromaDB wrapper: embedding and retrieval of SAP chunks, ADaM specs, legacy code. Domain-aware chunking, PubMedBERT embeddings.

**knowledge/admiral_functions.py** — `get_signatures()`/`signatures_block()`: real `args()` signatures for every function in `ALLOWED_DERIVE_FUNCTIONS`, fetched once via `r_layer/scripts/list_admiral_signatures.R` and cached in `knowledge/admiral_signatures.json`. Built but not yet injected into any prompt (Phase 1b item 4).

**knowledge/document_parser.py** — Parses SAP/protocol PDFs and ADaM specs: splits by section headers, tags section types (endpoints, populations, statistical methods, censoring rules), returns structured chunks with metadata.

**specs/metacore_loader.py** — `get_spec_variables(dataset_name)`: shells to `r_layer/scripts/list_spec_variables.R` to return the real per-dataset variable list from `specs/metacore_spec.rds` (via `metacore::select_dataset()`). Used to ground `adam_generator.py`'s derivation prompt in the actual spec.

**specs/define_reader.py** — Reads Define.xml, converts to metacore-compatible format. Wraps metacore `read_xml()`.

**specs/lot_builder.py** — Builds structured LoT objects from agent output. Validates entry completeness (table number, title, population, data source). Coverage-vs-SAP check belongs here (planned).

**templates/adam_templates.py** — `ADAM_INPUTS`: dataset → real `(variable, file_path)` list (currently ADSL, ADAE). `render_header()`/`render_footer()`: deterministically render the `library()` block, metacore load, `read_xpt()` calls, metacore check, and `xportr::xportr_write()` — no LLM involvement, so truncation/wrong-case/wrong-directory bugs are impossible by construction. `get_admiral_template()`: fetches the real `ad_adsl.R`/`ad_adae.R` content from the installed `admiral` package (`ADMIRAL_TEMPLATE_FILES`), cached in-process. Legacy `ADAM_SKELETON` remains for datasets not yet in `ADAM_INPUTS`.

**templates/tlf_templates.py** — TLF program skeletons: table structure, footnote placement, output conventions.

**r_layer/runner.py** — Executes generated R scripts via subprocess; returns structured success/failure with stdout/stderr/exit code.

**r_layer/validator.py** — Runs R validation scripts: metacore checks, reference dataset comparison, hash comparison.

**r_layer/scripts/run_adam.R** — Sources a generated ADaM program, runs it against SDTM input, saves the output dataset.

**r_layer/scripts/build_metacore_spec.R** — One-off build script: `metacore::define_to_metacore()` on `specs/define/adam_define.xml`, saved via `save_metacore()` to `specs/metacore_spec.rds`. Re-run only if the source Define.xml changes.

**specs/define/adam_define.xml** — Define-XML v2 for the CDISC pilot ADaM datasets (ADSL, ADADAS, ADLBC, ADTTE, ADAE), sourced from the installed `metacore` package's example data, not the pilot GitHub repo (which only has an incompatible Define-XML v1).

**r_layer/scripts/validate_metacore.R** — Runs metacore checks on a generated ADaM dataset against the spec; reports variable-level failures.

**r_layer/scripts/compare_reference.R** — Compares a generated ADaM dataset against pharmaverseadam reference via `admiral::expect_dfs_equal()`.

**r_layer/scripts/list_spec_variables.R** — Takes a dataset name arg, loads `specs/metacore_spec.rds`, runs `metacore::select_dataset()`, prints the variable list one per line. Called by `specs/metacore_loader.py::get_spec_variables()`.

**scripts/eval_lot.py** — Scores a generated LoT (default `data/lot_entries.json`) against `data/reference/pilot_lot.json` by normalized table number; prints precision/recall/F1 plus missed/spurious lists.

**scripts/gen_spec.py** — Phase 2c spec proposal: LLM proposes a per-dataset variable spec (variable/label/type/origin/derivation) from LoT entries + live SDTM column listing → `specs/proposed/<DS>.json`; `--approve` copies to `specs/approved/` (the human sign-off gate).

**scripts/eval_spec.py** — Scores a proposed/approved spec's variable set against the Define.xml spec (via `get_spec_variables()`); precision/recall/F1.

**r_layer/scripts/build_metacore_from_spec.R** — Builds a metacore object from a human-approved JSON spec (`specs/approved/<DS>.json`) → `specs/approved/<DS>_metacore.rds`. The tabular-input counterpart to `build_metacore_spec.R`.

**r_layer/scripts/list_admiral_signatures.R** — Prints the real `args()` signature for each admiral function name passed on the command line; flags names that aren't real admiral functions.

**cache/prompt_cache.py** — SHA256 prompt hashing and cache store. Cache hit returns the stored program; misses store output with hash key, model version, timestamp. Primary consistency mechanism.

**api/main.py** — FastAPI placeholder (POST /study, /generate/lot, /generate/adam, /generate/tlf, GET /study/{id}/status). Production target is a later phase; do not build it out yet.

**config.py** — All configuration: model names (pinned), API keys from env, paths, ChromaDB settings, cache settings, R executable path. Nothing hardcoded elsewhere.

**main.py** — Entry point: runs the full pipeline for a given study ID and SAP path.

**tests/** — Test suite: sap_reader, lot_generator, adam_generator, validator.

**data/** — Raw input, SDTM, generated ADaM, SAP PDFs, pharmaverseadam references. Gitignored. `data/reference/` holds eval targets: `pilot_lot.json` (CDISC pilot TLF list), ADaMIG/SDTMIG PDFs.
